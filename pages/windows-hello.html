Windows Hello

Category: Device-bound

Windows Hello provides a device-bound sign-in experience with biometrics or PIN and is central to Microsoft's passwordless strategy on Windows.

Technical details

Windows Hello has multiple authenticator variants with different key storage characteristics. If you're building allow lists, treat them as separate AAGUIDs.

  • Windows Hello Hardware Authenticator 08987058-cadc-4b81-b6e1-30de50dcbe96 Private key stored in a hardware-based TPM.
  • Windows Hello VBS Hardware Authenticator 9ddd1817-af5a-4672-a2b9-3e3dd95000a9 Virtualization-based Security (VBS) uses hardware virtualization and the Windows hypervisor to store private keys in the host machine's TPM.
  • Windows Hello Software Authenticator 6028b017-b1d4-4c02-b4b3-afcdafc96bb2 Private key stored in a software-based TPM.

Context

  • Windows Hello passkeys are focused on local, device-bound credentials, with key protection tied to platform security capabilities like TPM and VBS.
  • Operationally, treat Windows Hello as an endpoint-dependent option: user experience and available authenticator variant can differ by hardware and Windows security configuration.
  • Recent Microsoft 365 Message Center communication highlights that passkey experiences on Windows are evolving, so tenant rollout state and end-user readiness guidance remain important.
